Detailed App Description

AI Training Lab is a Windows-based environment for experimenting with AI agent collaboration, learning through feedback, assessment, and optimization. Its five active workspaces coordinate fifteen specialized agents in defined, sequential workflows.

Installation Guide · Public Dashboard

Five workspaces, fifteen specialized agents

Every workspace has its own agent prompts, independently chosen installed Ollama models, and local conversation history. Different roles help examine the same task from different perspectives; their outputs are AI-generated proposals and assessments, not independently verified facts.

1. Conference Room — Collaboration & Problem Solving

Strategist → Analyst → Engineer. A shared problem passes through three distinct perspectives. The Strategist frames goals and options, the Analyst examines assumptions, evidence and trade-offs, and the Engineer develops a practical technical approach. The result is a structured discussion and proposed solution, not automatically executed work.

2. Training Lab — Learning & Improvement

Tutor → Student → Evaluator → Improver. The Tutor introduces a topic and guidance; the Student attempts the exercise; the Evaluator reviews the response; and the Improver identifies ways to strengthen it. Each stage is recorded before the next one begins, creating a traceable feedback cycle. This is in-session learning through prompts and context: it does not change model weights.

3. Evaluation Lab — Assessment & Benchmarking

Assessor → Scorer → Benchmarker. These roles support examination of outputs, scoring against chosen criteria, and comparison of findings. The Lab can also evaluate a completed Training Lab session with a separately selected local Evaluator model, preserving the original session and recording structured scores, findings and provenance. Model-generated ratings should not be treated as objective proof of performance or real-world improvement.

4. Advisory Lab — Analysis & Recommendations

Analyst → Advisor. The Analyst explores a question, its context, and possible approaches. The Advisor formulates recommendations and their rationale. Suggestions remain advisory: the agents do not make operational changes, execute commands, or approve decisions on the user's behalf.

5. Optimization Lab — Performance & Optimization

Diagnostician → Optimizer → Validator. The Diagnostician identifies weaknesses or bottlenecks; the Optimizer proposes a focused improvement; and the Validator examines the proposed result and how it could be checked. This workspace produces reversible, measurable recommendations. It does not autonomously modify software, configuration, or model parameters.

Models, prompts, and session history

AI inference runs through locally installed Ollama models, with a separate model assignment for each active agent. Users can select from their installed models, obtain model-selection guidance and, after explicit confirmation, download another local model through Ollama. Fifteen role-specific system prompts define agent responsibilities and can be edited in the local application files. Workspace histories are kept in a local SQLite database, including results from completed stages.

Optional external services

The standard agent workflows use local Ollama. Separately, users may choose to connect their own ChatGPT account for an external advisor. Only a question and any additional discussion, pasted text or notes explicitly selected and submitted by the user are sent to OpenAI; local rooms are not synchronized automatically. The application does not accept OpenAI API keys.

ChatGPT Advisor — Subscription Requirements. Using the optional ChatGPT Advisor may require an eligible paid ChatGPT subscription. Availability and usage limits are determined by OpenAI.

AI Training Lab's local Ollama-powered features remain free to use without a ChatGPT subscription.

The optional personal RunPod connection can securely retain a token for the current Windows user and perform an explicitly requested, read-only account and GPU price/availability check. It does not create GPU instances, upload datasets, start paid jobs or enforce a provider-side budget. Actual model-weight fine-tuning (including LoRA training) is not enabled in this release.

Local-first design and privacy

The Lab is a private application running at 127.0.0.1:8765; Ollama uses 127.0.0.1:11434. The public website is documentation and a download entry point—not a hosted AI service, chat endpoint, or copy of the user's sessions. Basic local workflows can run offline once prerequisites and models are installed. For fully local operation, Ollama cloud features must also be disabled in Ollama's configuration. Session history is stored locally without application-level database encryption, so device or disk encryption may be appropriate.

Current scope: This is an experimental AI laboratory, not an accredited training service or certified benchmarking platform. Agent assessments are informative, while parameter fine-tuning and remote training remain unavailable.
