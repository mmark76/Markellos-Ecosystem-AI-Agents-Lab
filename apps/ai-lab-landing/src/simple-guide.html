Install and use AI Lab

Install or update in five steps (Windows)

Follow these steps when installing a new version. If this is your first installation, skip the backup in step 2.

  1. Download. Choose STABLE for normal use or BETA for testing from the public dashboard. New release filenames include the version, for example AI-Agents-Lab-Windows-vX.Y.Z.zip; older releases retain their original names.
  2. Stop & Backup. If upgrading, finish any active agent work, use Stop Local Server (v2.0.26+) or Ctrl+C in an older server console, and back up data/campus.sqlite3 from the old installation. A first-time installation has no old server or database to back up.
  3. Extract. Extract the downloaded ZIP to a new folder you control; do not run a BAT file from inside the ZIP or overwrite your previous installation. To keep your session history, copy the backed-up campus.sqlite3 into the new installation's data/ folder while both servers are stopped. Keep the old folder until you have verified the new installation.
  4. Start your server. From the new extracted folder, double-click Start AI Training Lab.bat for STABLE v2.0.26, or Start Local Server.bat for BETA v2.0.29. Easy Start checks requirements, requests separate approval before installing missing components or the initial local model, and offers an optional Desktop shortcut. Both launchers register the dashboard's local Open and Stop actions.
  5. Launch. When setup succeeds, the local server starts. Open http://127.0.0.1:8765/ in your browser. BETA also includes Open AI Lab.bat to start the server if needed and open the app. After the initial setup, the dashboard's Open AI Lab action works for both versions. Use Stop Local Server to shut down the server when finished.

Important for upgrades: Run Start AI Training Lab.bat (STABLE) or Start Local Server.bat (BETA) from your new ZIP folder before using dashboard Stop or Open; otherwise, those actions may still target an earlier installation. Stop requires v2.0.26 or later.

Detailed App Description ↗

Requirements and later launches

The Lab lets you experiment with fifteen specialized AI agents across five active workspaces, including the Tutor → Student → Evaluator → Improver learning-and-feedback cycle. It is free to use, needs no subscription, and runs on your own computer rather than on this public website.

Before you begin: Use a Windows computer with at least 3 GiB of free disk space and an Internet connection for any missing prerequisites or initial AI model downloads. Larger models may require substantially more disk space and memory.

Later launches: Easy Start remembers your Windows Desktop shortcut choice. Use the dashboard's Open AI Lab to open or start the server, and Stop Local Server to shut it down without restarting. Both require first-time setup using v2.0.26 or later. In STABLE v2.0.26 the server window stays visible; in BETA v2.0.29 it runs in the background and Info → View API Logs shows recent local API activity.

Which Windows .bat file should I use?

  1. Start AI Training Lab.bat — STABLE v2.0.26. The original launcher checks prerequisites, requests necessary approvals, and starts the local server.
  2. Start Local Server.bat — BETA v2.0.29. The renamed launcher performs the same first-setup checks and starts the local server in the background, without opening the browser.
  3. Open AI Lab.bat — BETA v2.0.29. Starts the local server if necessary, then opens the application in your browser, like the dashboard's Quick Start.
  4. setup-training-environment.bat — advanced training setup only. This separate file prepares local training libraries and is not needed to start the Lab. Optional model-weight fine-tuning remains disabled.

Ready: Visit http://127.0.0.1:8765/ after the server starts. Choose an installed Ollama model, then open Conference Room or Training Lab to start a session.

After the initial setup and local model downloads, the basic application can run offline. Installing or updating software or downloading additional AI models requires Internet access.

Technical Documentation

Rooms and their current status ({{RELEASE_VERSION}})

The WORKSPACE menu contains five active rooms. Each uses independently selected local Ollama models and has separate local history. The fifteen agents work through defined sequential roles.

  1. Conference Room - available. Strategist → Analyst → Engineer: collaborative analysis and proposals for problem-solving.
  2. Training Lab - available. Tutor → Student → Evaluator → Improver: a four-stage learning-and-feedback exercise that does not change model weights.
  3. Evaluation Lab - available. Assessor → Scorer → Benchmarker: assessment and benchmarking. Completed Training Lab sessions can also be reviewed using a separate local Evaluator model; original records remain unchanged. Scores are AI judgments, not independent proof.
  4. Advisory Lab - available. Analyst → Advisor: analysis and recommendations, without automatic execution.
  5. Optimization Lab - available. Diagnostician → Optimizer → Validator: proposals for measurable, reversible improvement, without model fine-tuning or configuration changes.

For more about each workspace and the available optional connections, open Detailed App Description.

Local runtime and privacy

The Lab server is available only at 127.0.0.1:8765 and talks to local Ollama at 127.0.0.1:11434. The public website does not run the Lab, host a model, collect conversations, or expose the local server. The released inference provider is Ollama only.

For fully local Ollama operation, disable Ollama cloud features using disable_ollama_cloud: true in %USERPROFILE%\.ollama\server.json while retaining other settings, and restart Ollama. Alternatively, set OLLAMA_NO_CLOUD=1 in the Ollama process environment. Use installed local models only. This additional setting matters: a local web address alone does not guarantee that Ollama cloud features are disabled.

Conversation history is stored in a local SQLite file (data/campus.sqlite3) without application-level encryption. Other people with access to the same Windows account or device may be able to read it. Use device encryption where needed.

Setup, models, and troubleshooting

Easy Start reuses compatible Python, Ollama, and existing local models. If a required component is missing, it requests a separate confirmation before installing Python, installing Ollama, starting the local Ollama service, or downloading the initial qwen2.5:0.5b model. If approval is declined, the required setup will not continue.

If the Lab does not start, first check that Easy Start completed, that Ollama is running locally, and that port 8765 is free. Use Stop Local Server to shut down the Lab, or Ctrl+C for older installations without the Stop action. Additional model downloads are optional and require approval and Internet access.

Feature status, updates, and reference

Advanced: Model Fine-Tuning (Optional) remains locked because the training worker is not yet compatible. The Local Lab includes a What is Fine-Tuning? A simple guide link that opens a beginner explanation in a separate tab. Reading the guide does not train or install anything. Updates are manual: stop the Lab, back up data/campus.sqlite3, then extract a new official ZIP separately and preserve your data and installed Ollama models.
